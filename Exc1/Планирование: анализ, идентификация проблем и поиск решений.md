### Анализ и идентификация проблем:

1) Проблемы с производительностью MES:
Длительная загрузка первой страницы MES (операторы тратят время, что снижает общую производительность).
Время расчёта стоимости заказа может достигать 30 минут, что увеличивает общую задержку обработки.

2) Нагрузка на инфраструктуру:
Линейный рост заказов привёл к увеличению нагрузки на системы (MES, CRM, API), что стало причиной задержек.
Один инстанс на каждое приложение и базу данных создает точку отказа и проблемы с масштабированием.

3) Проблемы с API:
Жалобы от внешних пользователей API на недоступность заказов.
MES API может быть узким местом, учитывая высокую нагрузку из-за расчёта стоимости и взаимодействия с CRM.

4) Увеличение задержек релизов:
Ручной тестировщик не справляется с большим объёмом работы, что приводит к пропуску багов или задержкам релизов.

5) Отсутствие автоматизации масштабирования:
Нет гибкости в масштабировании приложений и баз данных при увеличении нагрузки.


### Инициативы для устранения проблем в порядке приоритета:

1) Мониторинг, логгирование, трейсинг! Выявить проблемы с потерей заказов, долгих загрузок и ошибок. - чтобы устранять проблемы - нужно сначала понять их причину, для этого помогут эти инструменты.

2) Улучшение API, решение проблем с потерей и просрочкой заказов - это наиболее сильно влияет на прибыль, очень важно решить проблему, поставил бы ее на 1 место, но без наблюдения эту проблему не решить.

3) Масштабирование инфраструктуры - повысит производительность, а значит надежность и удовлетворенность клиентов:
Добавление горизонтального масштабирования для API, MES и CRM.
Введение реплик баз данных для разделения нагрузки на чтение и запись.

4) Оптимизация производительности MES - 30 минут ожидания слишком долго, влияет на мотивацию работников, а значит на прибыль:
Ускорение загрузки дашборда с заказами (оптимизация запросов, кэширование).
Перенос расчёта стоимости заказа в асинхронный процесс (удаление блокирующих операций).

5) Автоматизация тестирования - ускорение релиза, новых функций, удволетворенности клиентов:
Внедрение автоматизированных тестов (E2E, интеграционные).
Увеличение покрытия автоматизацией критически важных сценариев.

6) Рефакторинг CI/CD - ускорение релиза:
Автоматизация деплоя на релизные окружения.
Введение канареечных релизов и тестов на проде для быстрого выявления ошибок.



### Целевая архитектура через полгода:
- Микросервисная архитектура с горизонтально масштабируемыми компонентами и мониторингом.
- Базы данных с репликацией для обеспечения высокой доступности, кеширование частых запросов.
- Оптимизированная MES с асинхронной обработкой расчёта стоимости.
- Надёжный API с защитой от перегрузок.
- CI/CD с автоматическим деплоем на все окружения и тестированием на проде.

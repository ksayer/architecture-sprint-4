## Мотивация
Внедрение логирования в систему компании «Александрит» позволит:
1. **Сократить время на диагностику проблем.** Логи дадут прозрачность процессов и упростят анализ сбоев.
2. **Улучшить качество поддержки клиентов.** Сократится зависимость от слов клиента — данные будут подтверждаться логами.
3. **Повысить надёжность системы.** Логирование поможет своевременно выявлять и устранять нестандартные ситуации.
4. **Обеспечить соблюдение требований безопасности.** Логи зафиксируют все действия внутри системы, включая подозрительные операции.

**Метрики, на которые повлияет логирование:**
- Среднее время диагностики инцидентов.
- Среднее время восстановления после сбоев.
- Количество ошибок, выявленных на этапе логирования.

---

## Какие логи собирать
#### INFO
1. **Изменение статуса заказа (во всех системах):**
   - Время изменения.
   - Уникальный идентификатор заказа.
   - Старый и новый статус.
   - Пользователь/сервис, инициировавший изменение.

2. **Запросы к API (Internet Shop API, CRM, MES):**
   - Время запроса.
   - Метод и ендпоинт.
   - Идентификатор пользователя/сервиса.

3. **RabbitMQ:**
   - Время отправки сообщения.
   - Очередь и тема сообщения.
   - Уникальный идентификатор сообщения.

4. **Ошибки обработки сообщений (RabbitMQ, MES):**
   - Время ошибки.
   - Описание ошибки.
   - Данные сообщения, вызвавшего ошибку.

#### ERROR
1. **Неудачные запросы к API (500, 400):**
   - Код ошибки.
   - Ендпоинт.
   - Время.

2. **Системные сбои в RabbitMQ:**
   - Потерянные сообщения.
   - Очередь и топик.

---

## Приоритет систем
1. **RabbitMQ:**
   - Высокий риск потери сообщений.
   - Ключевая роль в передаче данных между сервисами.

2. **Internet Shop API:**
   - Главная точка взаимодействия клиентов.
   - Высокая частота обращений.

3. **MES:**
   - Критическая система для расчёта стоимости и производства.

4. **CRM:**
   - Поддержка взаимодействия с клиентами, менее подвержена техническим сбоям.

## Предлагаемое решение
**Технологии:**
- **ELK-стек (Elasticsearch, Logstash, Kibana):** для централизованного сбора, хранения и анализа логов.
- **Filebeat:** для отправки логов из систем в Logstash.
- **Alerting в Kibana:** для настройки уведомлений при аномалиях.

Ссылка с добавленными системами (Filebeat не добавлял к каждому сервису, иначе будет свалка непонятная)
https://drive.google.com/file/d/1HVXSSgTqsC1AaZOho2yHhYk16Hb_6JXg/view?usp=sharing

**Действия:**
1. Установить Filebeat на серверы Internet Shop API, CRM, MES и RabbitMQ.
2. Настроить Logstash.
3. Развернуть Elasticsearch для хранения логов с отдельными индексами:
   - Индекс для каждого сервиса.

4. Настроить Kibana для визуализации данных и дашбордов.

**Безопасность:**
- Все логи шифруются при передаче (TLS).
- Доступ к логам только для команды DevOps и разработчиков.

**Политика хранения:**
- Логи уровня INFO: 30 дней.
- Логи уровня ERROR: 90 дней.
- Архивирование устаревших логов в S3 для длительного хранения.

**Система анализа:**
- Настроить алерты в Kibana:
  - Например, частота ошибок API превышает 5% за 10 минут.
- Обнаружение аномалий:
  - Использовать машинное обучение в Elasticsearch для поиска аномального поведения (DDoS, всплеск заказов).

---

**Плюсы ELK-стека:**
- Масштабируемость.
- Мощные инструменты анализа и визуализации.
- Большая поддержка сообществом.

**Минусы ELK-стека:**
- Высокие требования к ресурсам.
- Требуется настройка и поддержка инфраструктуры.

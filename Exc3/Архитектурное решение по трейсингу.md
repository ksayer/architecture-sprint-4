# Архитектурное решение по трейсингу

## Мотивация
Внедрение трейсинга позволит:
1. **Обнаруживать и устранять узкие места в обработке заказов.**
2. **Снижать вероятность потери сообщений, влияющих на обработку заказов.**
3. **Ускорять диагностику инцидентов.**
4. **Повышать прозрачность процесса обработки заказов.**
5. **Увеличивать удовлетворённость клиентов за счёт сокращения времени на устранение проблем.**

**Метрики, на которые повлияет трейсинг:**
- Время отклика системы на каждом этапе обработки заказа.
- Количество успешно обработанных заказов.
- Количество заказов, застрявших на определённом этапе.
- Частота ошибок на уровне сервисов.
- Среднее время на устранение инцидентов (MTTR).

---

## Системы, которые следует покрыть трейсингом
1. **API интернет-магазина** — задержка или ошибки в передаче данных заказа.
2. **RabbitMQ** — потеря или зависание сообщений.
3. **CRM** — ошибки в обработке подтверждения заказов.
4. **MES** — задержки или сбои при расчёте стоимости и обработке заказов.

---

## Данные, которые должны попадать в трейсинг
1. Уникальный идентификатор заказа.
2. Время входа и выхода заказа из каждого сервиса.
3. Статус заказа после обработки (успех, ошибка).
4. Тип события (создание, обновление, завершение).
5. Ошибки, возникшие на этапе обработки.
6. Данные о повторных попытках обработки.
7. Имя и параметры очереди RabbitMQ.

---

## Предлагаемое решение
**Технологии и компоненты:**
- **Jaeger**/**OpenTelemetry** для сбора данных о трейсах.
- Интеграция трейсинга в RabbitMQ, API, CRM и MES.
- **Prometheus и Grafana** для визуализации трейсинга и настроек алертов.

**Действия:**

2. Добавить плагины для RabbitMQ для интеграции с трейсингом.
3. Настроить сбор трейсинговых данных в **Jaeger**.
4. Обновить схему системы, добавив Jaeger и новые связи (ссылка на схему ниже).

**Автоматический мониторинг и алертинг:**
- Настроить автоматическую проверку трейсинговых данных в реальном времени.
- Установить алерты в Grafana:
  - Если заказ застрял в одном статусе более 10 минут.
  - Если RabbitMQ сообщает о потерях сообщений.


---

## Компромиссы
1. **Сложности интеграции:** Проприетарные компоненты MES могут требовать значительных усилий для интеграции.
2. **Высокая стоимость хранения трейсинговых данных:** Необходима политика ротации данных для оптимизации затрат.
3. **Перегрузка системы:** Трейсинг может увеличить нагрузку на API и базы данных.

---

## Аспекты безопасности
1. Доступ к системе трейсинга только для сотрудников с ролью "Поддержка".
2. Шифрование всех данных трейсинга в хранилище и при передаче.
3. Мониторинг аномальной активности, связанной с доступом к данным трейсинга.
